# ログイン時起動から得た教訓

- `SMAppService.Status.enabled` は登録状態であり、`launchd` がヘルパーを実行できた証明ではありません。
- ログイン時起動の検証では、開発用 `dist` コピーではなく、実際にインストールしたバンドルを確認します。
- アドホック署名は `codesign --verify` に通っても起動制約で失敗する場合があります。`launchd` のジョブ、統合ログ、プロセス引数を確認します。
- 移行時は利用者のオプトイン設定を維持し、オフの設定に対してログイン用 Agent を勝手に作りません。
- 配布ビルド番号を本体とヘルパーで揃えて増やします。ただし、番号更新だけを実行時検証の代わりにはしません。
- 起動成功とする前にユーザーセッションでジョブを読み込み、プロセスと終了コードを確認します。最終受け入れには実際のログアウト／ログインでの確認を依頼します。
